# 🥑 FatSecret AI Voice Diary Bot

Персональный Telegram-бот для голосового и текстового подсчёта калорий с автоматической синхронизацией с мобильным приложением **FatSecret** на iPhone / Android.

## 🚀 Возможности

* 🎙 **Голосовой ввод:** Диктуйте съеденную еду голосом в Telegram (используется бесплатная модель Whisper-large-v3 от Groq).
* 🧠 **Умный парсинг (ИИ):** Нейросеть сама определяет граммы, штуки, миллилитры, раскладывает по белкам, жирам, углеводам и калориям.
* 📅 **Любые даты и мульти-записи:**
  * Понимает относительные даты: *«вчера на ужин»*, *«позавчера на обед»*, *«сегодня»*.
  * Понимает явные даты: *«18.10 на обед... 18.10 на ужин...»*.
  * Умеет принимать большие списки за несколько дней сразу.
* 📲 **Прямая синхронизация с FatSecret:** По кнопке подтверждения еда мгновенно появляется в дневнике в приложении на телефоне с точными граммами.

## 📁 Структура проекта

* `bot.py` — основной файл Telegram-бота (на базе `aiogram 3`).
* `ai_service.py` — распознавание аудиофайлов и структурирование продуктов через Groq API.
* `fatsecret_client.py` — клиент для работы с официальным API FatSecret (OAuth 1.0 3-legged авторизация, поиск продуктов и запись в дневник).
* `config.py` — загрузка переменных окружения.
* `requirements.txt` — список необходимых Python-библиотек.
* `.env.example` — шаблон для ключей доступа.

## 🛠 Установка и запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/misaains/MyDiaryFs.git
cd MyDiaryFs
```

### 2. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 3. Настройка ключей
Скопируйте `.env.example` в `.env`:
```bash
cp .env.example .env
```
Заполните переменные:
* `TELEGRAM_BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather)
* `GROQ_API_KEY` — бесплатный ключ с [console.groq.com](https://console.groq.com/keys)
* `FATSECRET_CONSUMER_KEY` и `FATSECRET_CONSUMER_SECRET` — ключи с [platform.fatsecret.com](https://platform.fatsecret.com)
* `ALLOWED_TELEGRAM_IDS` — числовой ID вашего Telegram-пользователя. Можно перечислить несколько ID через запятую. Пустой или некорректный список блокирует запуск; сообщения из групп и от посторонних игнорируются, включая нажатия кнопок.
* `TELEGRAM_PROXY` — необязательный HTTP CONNECT прокси для Telegram.
* `OUTBOUND_PROXY` — необязательный HTTP CONNECT прокси для Groq и FatSecret. Например, `http://127.0.0.1:8118` при запуске Python на хосте. Оставьте оба поля пустыми, если прокси не нужен.

По умолчанию читается `.env` рядом с исходниками. Другой путь можно задать через `MYDIARY_ENV_FILE`; переменные окружения имеют приоритет. Прокси не устанавливается самим ботом: укажите уже работающий HTTP-прокси, при необходимости соединённый с вашим VPN/SOCKS-туннелем.

### 4. Запуск бота
```bash
python bot.py
```

После первого запуска напишите боту команду `/login` в Telegram, перейдите по ссылке, нажмите «Разрешить» и отправьте полученный PIN-код боту для привязки вашего аккаунта FatSecret.

**Бот персональный:** все разрешённые ID используют один общий аккаунт FatSecret. Добавление второго ID не создаёт отдельный дневник. Привязка хранится в `fatsecret_user.json`; этот файл и API-ключи нельзя публиковать. Неподтверждённые записи живут в памяти и теряются при перезапуске.

## Docker и автозапуск на Linux

Требуются Docker Engine и Compose. Для каталога проекта:

```bash
mkdir -p config data
chmod 700 config data
cp .env.example config/bot.env
chmod 600 config/bot.env
# Заполните ключи и ALLOWED_TELEGRAM_IDS:
nano config/bot.env
docker compose up -d --build
```

Контейнер работает под UID/GID `1000:1000`; каталоги должны быть доступны этому пользователю. Если владелец файлов имеет другой UID/GID, измените `user` в `compose.yaml`. Образ использует Python 3.12 с закреплённым digest и проверенные версии библиотек из `requirements.lock`.

В Docker конфиг читается из `config/bot.env`. Для прокси на Linux-хосте используйте `http://host.docker.internal:8118` вместо `127.0.0.1`: внутри контейнера loopback указывает на сам контейнер. Прокси должен слушать адрес Docker-моста и разрешать подключения из контейнера; открывать его в интернет не требуется.

Если ключи или ID ещё не заполнены, контейнер ждёт конфиг, не выполняя запросов. После сохранения полного файла бот стартует примерно через 10 секунд. Для изменения настроек уже работающего бота:

```bash
docker compose restart bot
docker compose logs --tail=30 bot
```

`restart: unless-stopped` восстанавливает контейнер после падения и перезагрузки хоста, если Docker включён в автозапуск. После явной `docker compose stop` верните его командой `docker compose up -d`. Открывать входящие порты не нужно: бот использует polling. Время берётся с Linux-хоста через `/etc/localtime`; выставьте на хосте нужный часовой пояс для корректной обработки дат.

OAuth-привязка сохраняется в `data/fatsecret_user.json`. При переносе с компьютера скопируйте прежний файл в `data/`, ограничьте права (`chmod 600 data/fatsecret_user.json`) и перезапустите контейнер; либо привяжите аккаунт заново через `/login`. Старый процесс бота с тем же Telegram-токеном следует остановить. Для резервной копии сохраняйте вместе `config/` и `data/`.

Для уже загруженного сервера с большим количеством Docker-сетей проверьте, что новая bridge-сеть не пересекается с LAN и её адреса разрешены прокси/файрволом. При необходимости задайте свободную подсеть через Compose override.

## Проверки

Тесты не обращаются к Telegram, Groq и FatSecret:

```bash
python -m unittest discover -s . -p test_deployment.py -v
# Или внутри запущенного контейнера:
docker compose exec -T bot python -m unittest discover -s /app -p test_deployment.py -v
```

Проверяются чужие ID и callback-кнопки, групповые чаты, пустой список доступа, запуск без прокси и перечитывание заполненного конфига. `probe_network.py` отдельно проверяет сеть с заведомо недействительными ключами: Telegram и Groq должны ответить 401, FatSecret — JSON-ошибкой авторизации. Скрипт не отправляет сообщения, не вызывает генерацию и не записывает еду:

```bash
docker compose exec -T bot python /app/probe_network.py
```

Файл `data/runtime-status.json` показывает ожидание конфига или запуск процесса; он не подтверждает успешную авторизацию и доступность API. Проверка реального распознавания и сохранения дневника выполняется отдельно с вашими ключами.
